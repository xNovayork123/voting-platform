NOTE ON SESSIONS / COOKIES
The frontend now calls the API using RELATIVE paths (e.g. /api/ballots/).
package.json has  "proxy": "http://127.0.0.1:8000"  so the CRA dev server
forwards /api/* to Django. This keeps the browser on a SINGLE origin
(localhost:3000), so the Django session cookie is first-party and is sent
on every request. This is why login + session-protected actions now work.

Do NOT hardcode http://127.0.0.1:8000 in fetch() again: serving the page
from localhost while calling 127.0.0.1 makes the request cross-site, and a
SameSite=Lax session cookie is then refused on fetch/XHR.
